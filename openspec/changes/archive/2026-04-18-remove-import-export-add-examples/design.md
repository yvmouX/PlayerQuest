## Context

当前任务编辑器有导入/导出按钮，用户可以手动导入 JSON 配置文件或导出当前配置。但实际使用中：
- 导入功能很少被用到
- 导出功能与 Git 版本控制重复
- 新用户缺乏引导，不知从何开始

用户需要一个"一键加载示例"的功能来快速了解编辑器。

## Goals / Non-Goals

**Goals:**
- 移除导入/导出功能，简化界面
- 提供 3-5 个预设示例，覆盖常见任务类型
- 示例配置以 JSON 文件形式存储在 `assets/examples/` 目录

**Non-Goals:**
- 不做复杂的配置模板系统
- 不支持用户自定义保存为模板
- 不保留导出功能（Git 已做版本管理）

## Decisions

### 1. 示例对话框 vs 下拉选择

**决定**：新建 `ExampleQuestsDialog.vue` 弹窗组件

**理由**：示例数量可能扩展，弹窗可以展示更多信息（名称、描述、预览图）。下拉菜单适合 2-3 个选项，不适合未来扩展。

### 2. 示例配置文件格式

**决定**：使用 JSON 格式，存储在 `assets/examples/` 目录

**理由**：
- 与任务编辑器数据格式一致
- 可直接被 `loadQuests()` 函数解析
- 便于打包到 jar 文件中

### 3. 示例列表

| 文件名 | 名称 | 描述 |
|--------|------|------|
| `simple-quest.json` | 简单任务 | 单节点任务，只有一个 Start → Task → Completion |
| `daily-quest.json` | 每日任务 | 带重置间隔的任务 |
| `branching-quest.json` | 分支任务 | 使用 Branch 节点的条件分支 |
| `event-quest.json` | 事件任务 | 使用 Event 监听器触发任务 |

## Risks / Trade-offs

- **示例不够用** → 未来可扩展更多示例，或添加"在线示例库"功能
- **用户已有导入的自定义配置** → 无法迁移，需要用户手动重新创建（低频场景）
