# PlayerTaskX 使用文档

一个面向 Spigot / Paper / Folia / Canvas 的**每日任务与自定义任务**插件：
任务由「多个目标 + 多个奖励」组成，支持网页可视化编辑、游戏内 GUI、多语言与变量。

## 核心概念

### 任务（Quest）

一个任务 = **若干目标 + 若干奖励**。所有目标都完成后任务标记为「已完成」，
玩家在 GUI 或命令里**主动领取**奖励。

```
任务「挖矿日常」
├── 目标 1：挖掘 64 个石头
├── 目标 2：发言一次（内容包含「你好」）
└── 奖励 1：500 金币
```

### 任务类型

| 类型 | 说明 |
|---|---|
| `DAILY` 每日任务 | 从任务池按玩家抽取，跨天重置，可用货币刷新 |
| `NORMAL` 普通任务 | 常驻任务；**目前还没有发给玩家的入口**（只在编辑器与 `/ptxa list` 里可见），因此给它配前置暂时看不到游戏内效果 |

### 前置任务

一个任务可以绑定**多个前置任务**（也可以不绑定），不同任务各自配各自的前置，
形成任务链。判定标准是**已领取奖励**：前置任务全部领过奖之后，
本任务才会进入每日抽取池，也才能领取奖励。「已完成但还没领奖」不算数。

- 前置未满足的任务**不会被抽到**，玩家不会拿到一个做不了的任务；
- 已经发到手里的任务若被加上前置，领取时同样会被挡住（会提示还差哪几个）；
- 任务详情界面（GUI）会列出前置与各自是否已达成；
- 前置关系跨天保留：判定依据是一份**永久领取记录**，不随每日任务重置而清空。

> 前置写成不存在的 id、或两个任务互等（成环）时，目标任务会**永远解锁不了**。
> 这两种情况编辑器与 `/ptxa list` 都会标出来，别放着不管。

### 数据存储

任务定义、预设与玩家进度**都存在同一个数据库里**：默认 **SQLite**（零配置、单文件，
开箱即用），多服共享玩家数据时换成 **MySQL**。详见 [配置](configuration)。

除此之外还可以把任务/预设写成 `quests/`、`presets/` 下的 YAML 文件，作为**只读**来源补充进来
（数据库仍是唯一可写的那一份）。

## 特性一览

- **15 种任务目标**：挖掘、放置、合成、垂钓、自定义钓鱼、击杀、消耗、附魔、剪切、繁殖、驯服、交互、发言、提交、执行命令
- **5 种任务奖励**：金币（Vault）、点券（PlayerPoints）、经验、物品、自定义命令
- **货币可配置**：刷新费用的货币顺序在配置里指定（默认「金币 → 点券 → 经验」），
  没装经济插件的服务器自动用经验扣费，刷新功能在任何服务端上都可用
- **完全自定义**：一个任务可挂任意多个目标与奖励，参数由类型自身的 schema 描述
- **前置任务（任务链）**：一个任务可挂多个前置，全部**领奖**后才解锁；
  前置关系跨天保留，未解锁的任务不会被抽到
- **插件联动**：装了 **MythicMobs** 时击杀任务可指定自定义怪（`mythic:<怪物id>`，
  编辑器里能直接选）；装了 **CustomFishing** 时可用「自定义钓鱼」目标按鱼 id 与尺寸统计钓获
- **网页编辑器**：任务列表（搜索/筛选/排序/批量操作）、表单编辑、**YAML 文本编辑**、
  玩家进度、YAML 导入导出
- **定义也能写在文件里**：`quests/` 与 `presets/` 下的 YAML 是**只读来源**，适合随插件发布、
  进版本控制；空着时插件会铺一份示例（`example_file_` 前缀），数据库优先，同 id 冲突时告警并忽略文件里那份
- **游戏内 GUI**：玩家每日任务界面、任务详情、管理员任务管理
- **进度提示**：动作栏实时显示进度，任务完成时弹出标题提醒
- **多语言**：内置简中 / 英文，可自行增补语言文件
- **变量**：与 PlaceholderAPI 集成，可在计分板、菜单里展示任务信息
- **跨平台调度**：基于 YLib 的通用调度器，同一份代码在 Spigot / Paper / Folia / Canvas 上运行

## 运行要求

| 项目 | 要求 |
|---|---|
| 服务端 | Spigot / Paper / Folia / Canvas，1.21 及以上（`plugin.yml` 的 `api-version: '1.21'`） |
| Java | 21 |
| 软依赖（可选） | Vault（金币奖励）、PlayerPoints（点券奖励）、PlaceholderAPI（变量） |

> 软依赖缺失**不会导致插件无法启动**：对应的奖励类型会被标记为「不可用」，
> 并在启动日志与管理员界面里明确提示原因。

## 开发与构建

```powershell
.\start-folia.ps1              # 构建 + 复制到 run\plugins + 启动测试服
.\start-folia.ps1 -Clean       # 先 clean 再构建
.\start-folia.ps1 -Foreground  # 前台运行，可直接输入服务端命令
.\gradlew.bat build            # 只构建与跑测试
```

构建产物为 `build/libs/playerTaskX-<版本>-all.jar`（**部署请用这个 `-all` 版本**）。

架构说明见 [ARCHITECTURE.md](https://github.com/yvmouX/PlayerTaskX/blob/main/ARCHITECTURE.md)。
