# 常见问题

## 任务不涨进度

按顺序排查：

**1. 玩家有进行中的任务吗？**

```
/ptx list
```

没有输出说明今日任务未发放。玩家登录时才会发放，管理员可手动触发：

```
/ptxa resetperiod <玩家>
```

**2. 任务的目标类型是否被识别？**

```
/ptxa list
```

有问题的任务会被标红。若显示「未知目标类型 xxx」，说明 `target` 里的类型 id 写错了，
对照 [任务目标](objectives) 的 id 列检查。

**3. `target` 配置是否匹配？**

最常见的错误是**材质名写错**。注意：

- 必须用 **Bukkit 材质名**，如 `DIAMOND_ORE`（不能写「钻石矿」）
- 深板岩变种是**独立的材质**：`DEEPSLATE_DIAMOND_ORE`，不会与 `DIAMOND_ORE` 互相计入
- 实体类型同理：`ZOMBIE` `CREEPER`，不是中文名

用 `/ptxa info <任务id>` 能看到该任务目标的完整配置，与游戏内实际方块/实体对照。

**4. 任务的 `enabled` 是 true 吗？**

禁用的任务不再累计进度。`/ptxa info <任务id>` 会显示启用状态。

**5. 玩家的这条任务是否已完成？**

已完成（待领取）或已领取的任务不再累计进度，这是预期行为。用 `/ptx list` 看状态。

## 打了 MythicMobs 的怪 / 钓了自定义鱼，任务不涨

这两类目标依赖游戏内容插件，缺了一样是「配了但永远不涨」——先看 `/ptxa list` 有没有标红。

**击杀 MythicMobs 自定义怪**

| 情况 | 表现与处理 |
|---|---|
| 没装 MythicMobs | `target: mythic:xxx` 会被标成校验问题 | 
| 装的是 MythicMobs 4.x | 启动日志会写「只支持 5.x」（4.x 不支持 1.21+） | 
| 装好了但仍不涨 | 确认 `mythic:` 后面写的是**内部名**（`/mm mobs list` 里的 id），不是显示名；名称大小写不敏感 |
| 想让自定义怪也算原版任务 | 直接配 `target: ZOMBIE` 即可：自定义怪同时算它的原版类型，一次击杀只计 1 次 |

**钓 CustomFishing 的自定义鱼**

- 必须用**「自定义钓鱼」（`custom_fish`）**目标，不能用原版「垂钓」：
  自定义钓获由 CustomFishing 自己的战利品表产出，原版垂钓事件看不到它
- `target` 写 CustomFishing 配置里的鱼 id；填了 `min-size` 时，**没有尺寸信息的钓获不算达标**
- 没装 CustomFishing 时该目标类型在编辑器里直接标为「不可用」

## 奖励拿不到

**1. 先看奖励类型是否可用**

```
/ptxa list
```

若显示「奖励类型 money 不可用（未安装 Vault 或没有经济插件）」，说明依赖缺失：

| 奖励类型 | 需要的插件 |
|---|---|
| `money` | Vault + 任一经济插件（EssentialsX / CMI 等） |
| `points` | PlayerPoints |
| `exp` / `item` / `command` | 无依赖 |

**2. 任务完成了但领取失败？**

奖励需要**主动领取**：在 GUI 里点击任务，或执行 `/ptx claim <任务id>`。
任务完成不会自动发放。

管理员可强制补发（不改变任务状态）：

```
/ptxa grant <玩家> <任务id>
```

**3. 命令类奖励没有生效？**

- 命令**不能带前导斜杠**：写 `give %player% diamond 1` 而不是 `/give ...`
- 检查控制台是否有该命令的报错——命令由控制台执行，失败会打印在控制台

## 进度显示在屏幕中间

说明服务端**没有** `sendActionBar` API（非 Paper / Folia 系服务端），
插件退回到了「副标题」位置显示。

启动日志里会明确写出走的是哪条路径：

```
[playerTaskX] 进度将通过动作栏（actionbar）显示。          ← 正常
[playerTaskX] 服务端未提供 sendActionBar(String)…          ← 回退到副标题
```

若确实想关掉进度显示：`progress.actionbar: false`。

## 中文显示成乱码

**现象**：控制台里插件输出的中文是 `宸茬敓鎴愯` 这样的乱码，
但 `plugins/playerTaskX/lang/zh_CN.yml` 里的内容是正常的。

**原因**：这是 Windows 控制台的编码问题，**不是插件的问题**——日志文件本身是正确的 UTF-8。

**处理**：

1. 启动服务器时加 JVM 参数（本项目的 `start-folia.ps1` 已经带了）：
   ```
   -Dfile.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8
   ```
2. 或在 PowerShell 里先执行 `chcp 65001`，或直接用 Windows Terminal
3. 直接看日志文件（`logs/latest.log`）内容是正确的

## 网页编辑器打不开

**1. 确认已启用且端口未被占用**

```yaml
editor:
  enabled: true
  port: 28080
```

启动日志应出现：

```
[playerTaskX] 网页编辑器已启动：http://127.0.0.1:28080
```

端口被占用时会自动 +1 重试（最多 10 个），日志出现 warn 说明实际使用的端口；
`/ptxa editor` 输出的也是实际端口。若日志出现「连续 10 个端口都被占用」，
请修改 `editor.port` 后重启。

**2. 是远程服务器？**

默认监听所有网卡，从外部访问需要放行防火墙端口。若访问后所有操作都返回 401，
说明配置了 `editor.token`，需要在页面左下角填入令牌。

**3. 页面空白 / 404**

插件 jar 里的前端资源缺失（极少数情况，通常是自行构建时未生成）。
用 `/ptxa editor` 确认地址，并检查日志。

## 刷新周期任务失败

| 提示 | 原因 |
|---|---|
| `金币不足，需要 xxx` / `点券不足，需要 xxx` / `经验不足，需要 xxx（当前 yyy）` | 对应货币的余额不够（`periodic.<类型>.refresh-cost`）。提示里会写明实际扣的是哪种货币 |
| `今日刷新次数已用完（上限 N 次）` | `periodic.<类型>.refresh-limit` 限制 |

想让刷新免费：把对应周期的 `refresh-cost` 设为 `0`。

> **管理员用 `/ptxa resetperiod` 重置不收费、也不消耗刷新次数**——它是排障工具。
> 若连它都提示经济相关的问题，说明是插件的 bug，请反馈。

## 跨周期没重置任务

检查对应周期的 `reset-hour`（每周还看 `reset-weekday`，每月看 `reset-month-day`）：

```yaml
periodic:
  daily:
    reset-hour: 4
```

**早于该时刻算作上一个周期**。设为 `4` 时，凌晨 3:30 仍属于前一天的周期。
若希望零点就重置，设为 `0`。

插件每 5 分钟检查一次是否跨周期，玩家登录时也会检查，因此重置不会延迟太久。
自定义周期（`period: 3d` / `12h`）没有「几点重置」这回事，长度一到就换。

## 改了任务但游戏里没变化

任务定义存在数据库里，内存中是缓存。编辑器与 `/ptxa` 命令保存的都是**立即生效**的
（落库的同时更新内存缓存与玩家进度索引），只有换了库、改了 `quests/` 里的文件、
或在插件外直接改了数据才需要重载：

```
/ptxa reload
```

网页编辑器保存的任务不用走这一步。若玩家仍看到旧进度，让该玩家重新登录一次
（进度索引在登录时重建）。

## 某个任务在编辑器里改不动（保存/删除是灰的）

那个任务的定义来自 `plugins/playerTaskX/quests/` 下的 YAML 文件，属于**只读来源**：
插件只在这两个文件夹空着时铺一次示例，之后从不写入；游戏内与网页编辑器只修改数据库里的定义。

- 改它：直接改文件，然后 `/ptxa reload`
- 搬进数据库：在列表页「导出 YAML」，删掉原文件后再「导入 YAML」
- 同一个 id 两边都有时**以数据库为准**，文件里那份会被忽略——启动日志里有告警；
  因此「导入了却没变」通常是这个原因，把 `quests/` 里的同名文件删掉或改名即可
- 完全不想读文件：`definitions.read-files: false`

> `example_file_` 前缀的那些就是插件铺的示例（默认 12 个任务 + 11 个预设）：删掉即可，
> 只要目录里还有任何一个 YAML，插件就不会再补；整个目录清空则下次启动会重新铺一份。

见 [配置 · 用 YAML 文件写定义](configuration?id=用-yaml-文件写定义)。

## MySQL 连不上

- 确认 `storage.type: MYSQL` 且 `storage.mysql.default` 各项填写正确
- 修改存储配置后**必须重启服务器**（存储类型在启动时确定）
- 数据库需要**预先创建**，插件只建表不建库：
  ```sql
  CREATE DATABASE playerTaskX DEFAULT CHARSET utf8mb4;
  ```
- 从 SQLite 切到 MySQL **不会自动迁移数据**

## 如何备份任务

**方式一：网页编辑器导出**

在任务列表页点「导出全部」（或勾选若干条后点「导出选中（N）」），会下载
`playerTaskX-quests.zip`——里面**一个任务一个 `.yml`**；只选一条时直接是一个
`<任务id>.yml`。需要时用「导入 YAML / ZIP」还原（可选合并或替换——**替换只清数据库**，
`quests/` 里的只读文件不受影响）。

导出的 `.yml` 与 `plugins/playerTaskX/quests/` 里的文件是同一种格式：想让任务以文件形态
长期维护、进版本控制，把这些文件解压后直接放进去即可，插件会当作只读定义读取。
见 [配置 · 用 YAML 文件写定义](configuration?id=用-yaml-文件写定义)。

**方式二：直接备份数据库**

- SQLite：备份 `plugins/playerTaskX/data/playerTaskX.db`
- MySQL：用 `mysqldump` 备份对应库

## 插件启动失败 / 被禁用

控制台会写明原因：

| 日志 | 处理 |
|---|---|
| `YLib 初始化失败` | YLib 已被其它插件初始化，或服务定位失败；检查是否装了依赖同一 YLib 的插件 |
| `配置加载失败，插件将被禁用` | `config.yml` 格式有误；删掉让它重新生成，或按 [配置](configuration) 修正 |
| `数据库打开失败，插件将被禁用` | 检查文件权限（SQLite）或连接信息（MySQL） |

其它子系统（命令注册、编辑器、变量）失败**不会**导致插件被禁用，
只会在日志里记录「初始化「XXX」失败，该功能将不可用」。
