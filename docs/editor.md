# 网页编辑器

插件内置一个网页管理界面，用于创建与管理任务、查看玩家进度。

比手写 YAML 或翻数据库快得多，也是**推荐的任务管理方式**。

---

## 打开方式

浏览器访问：

```
http://<服务器地址>:<editor.port>
```

端口默认 `28080`；被占用时自动 +1 重试（最多 10 个），实际端口以启动日志为准，`/ptxa editor` 始终报告实际端口。若在服务器本机操作，可直接执行命令拿到地址：

```
/ptxa editor
```

它会输出地址，以及配置了访问令牌时的令牌内容。

---

## 安全

```yaml
editor:
  enabled: true
  port: 28080
  token: ""            # 留空 = 不校验
```

- **未设置** `token`：任何能访问该端口的人都能修改任务。插件会在启动日志里给出警告。
  仅建议在本机或内网使用。
- **设置了** `token`：页面左下角填入令牌后才会生效（浏览器会记住），
  所有 `/api/*` 请求都会带上它。

对公网开放的服务器请**务必**设置令牌，并用防火墙限制来源 IP。

> 编辑器只监听 HTTP，不提供 HTTPS。若要跨公网使用，建议放在反向代理（Nginx / Caddy）后面
> 由代理层负责 TLS 与访问控制。

## 界面说明

### 概览

首页仪表盘：任务总数、周期任务数（按四种周期分开列）、目标/奖励类型数、玩家数、当前存储类型，
以及全部目标类型与奖励类型的清单（奖励类型不可用时标注原因）。

提供「重载任务」按钮，等价于 `/ptxa reload`。

### 任务列表

任务的集中管理入口：

| 能力 | 说明 |
|---|---|
| 搜索 | 按 id 或名称模糊匹配 |
| 筛选 | 按类型（每日 / 普通）、分类、启用状态，以及「只看有问题的任务」 |
| 排序 | 点击表头按 id / 名称 / 类型 / 目标数排序 |
| 分页 | 每页条数可选 |
| 批量操作 | 多选后批量启用 / 禁用 / 删除 |
| 单行操作 | 编辑、复制、启用开关、删除 |
| 校验标记 | 配置有问题的任务会标红，鼠标悬停显示具体问题 |
| 来源标记 | 来自 `quests/` 的**只读**定义：整行压暗 + 灰色「只读 · YAML」徽标（见下） |

顶部的统计条会汇总「共 N 个 / 启用 N / 每日 N / 有问题 N」。

### 任务编辑

- **基础信息**：id、名称、描述、图标、分类、类型、刷新费用、启用开关
- **目标**：添加/删除/排序，字段按所选类型自动生成
- **奖励**：同上，不可用的奖励类型会被禁用并显示原因
- **YAML 视图**：右上角「可视化 / YAML」一键切换（见下）
- **未保存提示**：有改动未保存时，离开页面会提醒

目标与奖励的**顺序有意义**：管理员命令 `/ptxa setobjective` 里的「目标序号」
就是这里的排列顺序（从 `0` 开始）。界面卡片上显示的 `#N` 是**从 1 开始**的展示编号。

### YAML 视图：手写任务配置

右上角的「**可视化 / YAML**」开关把同一个任务换成文本编辑：

```yaml
id: example_daily_build
name: <yellow>添砖加瓦
description:
  - <gray>放置 64 个圆石
icon: BRICKS
category: 每日
type: DAILY
refreshCost: 1000
enabled: true
objectives:
  - type: place_block
    properties:
      target: COBBLESTONE
      amount: 64
rewards:
  - type: exp
    properties:
      amount: 300
```

几条约定：

- **字段名与「导出 YAML」完全一致**，两者可以互相粘贴；目标/奖励仍是
  `type` + `properties` 两层，因此新增目标类型不需要改编辑器
- **边写边生效**：文本会实时解析并写回表单，右侧的实时预览与左侧的校验问题都跟着变；
  解析不过去时只显示错误、**不动表单**（不会把你的内容清空），此时点保存会被拒绝
- **切回可视化前必须先解析成功**，否则表单显示的会是你以为已经改掉、其实没生效的旧内容
- 顶层的**未知字段会列成警告**（例如把 `rewards` 写成 `reward`），不会被悄悄丢掉
- 写错的地方（不存在的目标类型、缺少目标、`mythic:` 但没装 MythicMobs…）
  仍由后端校验标红，与表单模式同一套结论
- **注释与排版不保存**：数据库里存的是字段值，YAML 只是它的一种写法；
  每次切到 YAML 都会用当前内容重新生成。想保留注释就把它放进 `quests/` 目录，
  那份定义是只读的，注释随文件一起留着（见下）

> 预设管理页的每条预设也有同样的开关，适合从文档里粘一段 `type + properties`。
> 想批量导入/导出整份任务清单，用任务列表页的「导出 YAML / 导入 YAML」。

### 只读定义：来自 `quests/` 的 YAML 文件

插件会读取数据目录下 `quests/`（任务）与 `presets/`（预设）两个文件夹里的 YAML 定义，
它们**只读**——库优先，游戏内与编辑器只修改数据库里的定义（见
[配置 · 用 YAML 文件写定义](configuration?id=用-yaml-文件写定义)）。

**文件夹空着时插件会铺一份示例进去**（12 个任务 + 11 个预设，id 是 `example_file_` 前缀），
所以任务列表里通常同时有两套示例：库里那套（`example_` 前缀）可以随便改、随便禁用，
文件里那套用来对照文件格式。删掉文件里的示例即可，插件不会再补（目录非空就不写）。

编辑器里的表现：

- 任务列表里这类任务**整行压暗**，id 旁是灰色的「**只读 · YAML**」徽标；
- 这类任务的**启用开关与删除按钮是禁用的**，编辑页顶部的保存 / 复制 / 删除也都不可用，
  YAML 视图只读；表单整体是灰的、点不动（省得填完一场才在保存时被拒）；
- 批量启用 / 禁用 / 删除会**跳过**它们并提示跳过了几个，不会一半成功一半 409；
- 预设列表里的只读预设同样压暗并标「只读 · YAML」，但**套用到任务里照常可用**
  （只读说的是这条预设本身改不了）；
- 任务编辑页会写明这份定义来自哪个文件，并给出两条出路：改文件后 `/ptxa reload`，
  或「导出 YAML」→ 删除原文件 → 「导入 YAML」把它搬进数据库。

> 硬要绕过编辑器直接调接口改它也没用：后端返回 `409` 并说明原因，
> 判定在所有写入路径的共同入口上，不是只靠前端的按钮禁用。

### 图标与材质选择

图标、材质、实体这类字段不再需要手打枚举名，点击后弹出选择器：

- **每个字段只列它真正能填的东西**：值域由目标类型自己声明（见下），因此「挖掘方块」
  只列方块、不会出现苹果；「剪切」只列羊与蘑菇牛、不会出现猪；「附魔」只列附魔。
  这是「配了却永远不命中」的第一道防线
- 搜索框**同时匹配中文名、英文名和枚举名**——输入 `钻石`、`diamond`、
  `DIAMOND_ORE` 都能找到钻石矿石
- **可按插件来源筛选**：装了哪些插件就出现哪些来源标签（`原版` / `MythicMobs` /
  `ItemsAdder` / `CraftEngine` / `CustomFishing`），与「方块 / 物品 / 食物」分类、
  搜索关键词三者叠加生效。只有**当前字段范围里真的有内容**的来源才出现
  （实体字段不会冒出 ItemsAdder 标签，只有原版时整排标签不显示）；
  非原版条目右侧还会标出来源，一眼能分辨它是谁家的
- 按「方块 / 物品 / 食物」分类浏览，实体单独一栏
- 列表只包含**当前服务端版本支持**的物品（能作为物品存在的那些），
  因此不会选到本版本没有的东西
- 材质字段支持**多选**（逗号分隔），例如同时把两种钻石矿算作一个目标；
  仍然可以直接手打，逗号分隔的原始写法对熟悉 Bukkit 的管理员更直接
- 留空的字段表示「任意」，选择器不会强制你填
- 装了 **MythicMobs** 时，实体列表里会额外出现自定义怪（显示成 `MythicMobs: 名字`），
  选中后写入的就是 `mythic:<怪物id>` —— 也就是击杀任务要用的写法
- 装了 **ItemsAdder** / **CraftEngine** 时，它们的**自定义方块与物品**会一并进材质列表
  （显示成 `CraftEngine: default:amethyst_torch`，写入 `target` 的值是带前缀的
  `craftengine:default:amethyst_torch`）；同一个 id 既是方块又是物品时只列一条，避免重复
- 装了 **CustomFishing** 时，「自定义钓鱼」目标的**「鱼 id」字段也变成选择器**，
  列出它注册表里的战利品（显示 CustomFishing 配置里的 `nick`）。
  鱼单独一栏、不混进材质列表：把鱼 id 填进方块目标的 `target` 只会永远命中不了
- **手打或从文件/导入进来的值同样会被校验**：选择器拦不住的路径（YAML、导入的 zip、
  直接改库）由服务端按同一份值域声明复判——写了「挖掘 APPLE」这类永远不可能命中的配置，
  右侧「后端校验问题」会直接说明原因，而不是等玩家来问「我挖了怎么不涨」
- **来源与分类两排标签互相约束**：只列「另一个也满足时真的有东西」的选项，
  因此不会出现「点了没结果」的组合；换了一个筛选器后，另一个已选不到东西的会自动回到「全部」。
  计数显示的是**当前筛选后**的条数
- **缺软依赖的类型会被标灰**：没装 CustomFishing 时「自定义钓鱼」在下拉里显示「不可用」，
  没有可用经济服务（没装经济插件）时「金币」奖励同理；已经用了这类类型的任务会在右侧「后端校验问题」里列出原因

英文名直接来自服务端自带的语言文件，**与当前版本严格对齐**。

中文名需要额外获取，因为 Minecraft 服务端**不自带中文语言文件**（只有英文）。
插件会优先读 `plugins/playerTaskX/editor/zh_cn.json`；文件不存在时会在后台从官方资源下载
一份并缓存到该路径，之后不再重复下载。

- 只要成功取到一次，之后即使服务器访问不了外网也一直有中文名
- 完全离线的服务器可以手动把 `zh_cn.json` 放到上述路径，效果相同
- 若下载被关闭或失败，列表会显示英文名，**用英文名或枚举名照样搜得到**，
  界面上也会明确提示当前只有英文名

> 位置在 `editor/` 而不是 `lang/`：`lang/` 里是**插件自己的语言文件**（`zh_CN.yml`），
> 这份 `zh_cn.json` 是 **Minecraft 的译名数据**，只给编辑器图标列表用。

> 关闭下载：把 `config.yml` 里的 `editor.fetch-chinese-names` 设为 `false`。
> 有些服务器不允许插件访问外网，这种环境建议关闭并手动放置语言文件。

### 目标与奖励的预设

反复填写「挖 64 个石头」这类相同配置很费事。预设把这些配置存下来，建任务时
点一下就能套用：

- 在任务编辑器里点「添加目标 / 添加奖励」时，可以直接选一个预设套用，
  也可以从空白开始（弹层里有搜索框，预设多了按名称 / id / 类型一搜就到）
- 反向也支持：把当前正在编辑的目标/奖励**另存为预设**
- 「预设」页面可以新建、修改、删除预设

### 任务直接「引用」预设

套用是一次性复制；想让任务**跟着预设走**，就在定义里引用它（预设改一次，所有引用它的任务一起变）：

```yaml
# quests/example_file_daily_mine.yml
objectives:
  - preset: mine-stone        # 引用预设：类型与字段都由它提供
    properties:
      amount: 128             # 任务自己写的字段覆盖预设里的同名值
rewards:
  - preset: reward-exp        # 奖励同理
```

- 引用写在 `quests/*.yml`、编辑器的 YAML 视图、导入的文件里都可以；
- **改预设即改所有引用它的任务**：编辑器里保存预设后会立刻重算（不需要 reload），
  文件里的预设改完仍要 `/ptxa reload`；
- 编辑器的可视化表单里，这类条目显示为「引用预设 xxx」，字段是灰的、显示的是**生效值**；
  要单独调数值就到 YAML 视图写 `properties` 覆盖项，或点「展开为独立配置」把它变成普通配置
  （展开后就不再跟随预设了）；
- 引用写错（预设不存在、或拿奖励预设当目标用）会在校验问题里标出来 —— 这类错误表面上看
  任务还在，实际那个目标/奖励不生效；
- 删掉一个还被引用的预设：引用变成悬空，校验会报「引用的预设 xxx 不存在」。

> 预设仍然不是引擎概念：引擎看到的永远是展开后的生效值，展开发生在载入任务定义时
> （见 `ARCHITECTURE.md` 4.7）。

「预设」页面左侧是**标签页切换的两类列表**（目标预设 / 奖励预设，各带条数），下面有搜索框，
列表自己滚动——两类预设混在一列里、条目一多就要滚很久，切换标签比滚动省事得多。

预设存在数据库的 `preset` 表里（与任务定义、玩家数据同一个库，见 [配置](configuration#存储)），
编辑器里可以新建、修改、删除。插件**首次启动、库里还没有预设时**会写入一批默认预设作为示例
（`presets/` 目录里那份文件示例不影响这个判断：两套是并存的，id 前缀也不同）。

预设页右上角有「导出 YAML / 导入 YAML」：导出的是**两类一起**的清单
（`playerTaskX-presets.yml`，每项带 `kind`），导入时文件里没写 `kind` 的项按当前类别归档。
把预设放进 `presets/` 目录也可以，那样是只读的（见
[配置 · 用 YAML 文件写定义](configuration?id=用-yaml-文件写定义)）。

> 没有被任何任务引用的预设，删掉不影响任何任务；被引用的删掉会让那些任务出现校验问题
> （目标/奖励不生效），修好引用即可恢复。

### 玩家进度

排查「某玩家为什么没有进度」的入口：

- 左侧列出所有有任务数据的玩家，可搜索，在线玩家有标记
- 选中后右侧显示该玩家的任务记录：任务名、类型、状态、进度百分比、过期时间
- 展开可见**逐个目标的「当前 / 需求」**，一眼看出卡在哪一步
- 点击某位玩家会把该玩家写进地址栏（`#/players/<uuid>`）：这个地址可以直接分享、收藏，
  刷新或直接打开都停在同一位玩家（没带 uuid 时默认选中第一位）

该页面为**只读**，修改玩家数据请用 `/ptxa` 命令。

> 文案不在编辑器里改：语言文件是 `plugins/playerTaskX/lang/<语言代码>.yml`，
> 改完执行 `/ptxa reload`。见 [配置 · 语言](configuration?id=语言)。

### 导入 / 导出

**一个文件一条定义**，这是这套接口唯一的形状：

- **导出**：导出一条任务 → 下载 `<任务id>.yml`（这个文件可以直接放进 `quests/` 目录用）；
  勾选多条（导出按钮会变成「导出选中（N）」）或直接导出全部 → 下载 `playerTaskX-quests.zip`，
  里面一个任务一个 `.yml`
- **导入**：选 `.yml` / `.yaml` → 导入一条；选 `.zip` → 导入里面全部 `.yml`（每个文件一条）
- 导入方式（两种都只影响**数据库**）：
  - **合并**：保留现有任务，同 id 会被覆盖
  - **替换**：先清空**数据库里**的全部任务再导入（相当于用备份还原）
- 单文件导入前浏览器会先解析一遍，把 YAML 语法错误、「文件里是列表」「没有可用的任务定义」
  挡在提交之前；zip 不在浏览器里拆包（条数以后端结果为准）
- 导入结果会显示成功数量与被跳过的条目：缺 `id` 的、以及**来自 `quests/` 的只读 id**
  （它们本来就不是「导入」能改的那一份，逐条说明原因，不会打断整包导入）
- `replace` 只清数据库，**不会删 `quests/` 里的文件**——那些定义本来就只读

> **文件里是列表会被拒绝**并提示改用 zip（`- id: ...` 这种旧的整份清单形状）。
> 宽松地接受列表，会让「导入了一个文件却多出十几条任务」变成静默行为；
> 真要一次导入多条，打包成 zip 即可（`quests/` 里的文件格式就是 zip 里的格式）。
> 预设页的导入/导出规则完全相同，只是文件名换成 `playerTaskX-presets.zip`。

## 表单为什么是自动生成的

任务目标与奖励的参数由**类型自身的 schema** 描述：

```java
public interface ObjectiveType {
    String id();
    String displayName();
    List<ConfigField> schema();     // ← 表单据此渲染
    int match(ProgressContext context, Map<String, Object> properties);
}
```

因此编辑器（以及游戏内 GUI）**不需要为每种类型写界面代码**：
新增一种目标或奖励类型时，只要实现接口并注册，编辑器里立刻就能编辑它。

这也是编辑器里看不到任何「专门为某个类型写死的输入框」的原因。

`ConfigField` 的类型决定了渲染成什么控件：

| 类型 | 控件 |
|---|---|
| `STRING` | 单行文本 |
| `INTEGER` / `DECIMAL` | 数字输入 |
| `BOOLEAN` | 开关 |
| `MATERIAL` | 材质选择器（支持逗号分隔多选） |
| `ENTITY` | 实体选择器 |
| `TARGET` | 方块或实体选择器（两者都可选） |
| `ENUM` | 下拉，候选项来自 `options` |

> 写新类型时请**如实声明字段类型**：把「材质名」声明成 `STRING` 不会报错，
> 但编辑器只好给你一个纯文本框，管理员就得去查 Bukkit 枚举名——
> 这类字段应当用 `MATERIAL` / `ENTITY` / `TARGET`。

## 任务改动何时生效

编辑器保存会**立即生效**：写库的同时更新内存里的任务定义并重建玩家进度索引，
不需要重载，也不需要重启服务器。

概览页的「重载任务」按钮（等同 `/ptxa reload`）用于**从数据库重新读一遍**——
在插件外直接改过库、或换了存储后端之后才用得上。

> 玩家进度与任务定义按**目标下标**关联。插件会记录接手任务时的目标结构指纹，
> 大幅调整目标顺序（或增删目标）后，该任务上已有玩家的进度会被**重置为 0 并在日志里告警**，
> 而不是静默错配到别的目标上。建议在任务尚未发放给玩家时调整顺序，
> 或让玩家刷新周期任务（`/ptx refresh`）重新抽取。
