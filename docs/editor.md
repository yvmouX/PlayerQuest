# 网页编辑器

插件内置一个网页管理界面，用于创建与管理任务、查看玩家进度、编辑语言文件。

比手写 YAML 或翻数据库快得多，也是**推荐的任务管理方式**。

---

## 打开方式

浏览器访问：

```
http://<服务器地址>:<editor.port>
```

端口默认 `28080`；被占用时自动 +1 重试（最多 10 个），实际端口以启动日志为准，`/ptxa editor` 始终报告实际端口。若在服务器本机操作，可直接执行命令拿到地址：

```
/ptxa editor
```

它会输出地址，以及配置了访问令牌时的令牌内容。

---

## 安全

```yaml
editor:
  enabled: true
  port: 28080
  token: ""            # 留空 = 不校验
```

- **未设置 `token`**：任何能访问该端口的人都能修改任务。插件会在启动日志里给出警告。
  仅建议在本机或内网使用。
- **设置了 `token`**：页面左下角填入令牌后才会生效（浏览器会记住），
  所有 `/api/*` 请求都会带上它。

对公网开放的服务器请**务必**设置令牌，并用防火墙限制来源 IP。

> 编辑器只监听 HTTP，不提供 HTTPS。若要跨公网使用，建议放在反向代理（Nginx / Caddy）后面
> 由代理层负责 TLS 与访问控制。

## 界面说明

### 概览

首页仪表盘：任务总数、每日任务数、目标/奖励类型数、玩家数、当前存储类型，
以及全部目标类型与奖励类型的清单（奖励类型不可用时标注原因）。

提供「重载任务」按钮，等价于 `/ptxa reload`。

### 任务列表

任务的集中管理入口：

| 能力 | 说明 |
|---|---|
| 搜索 | 按 id 或名称模糊匹配 |
| 筛选 | 按类型（每日 / 普通）、分类、启用状态，以及「只看有问题的任务」 |
| 排序 | 点击表头按 id / 名称 / 类型 / 目标数排序 |
| 分页 | 每页条数可选 |
| 批量操作 | 多选后批量启用 / 禁用 / 删除 |
| 单行操作 | 编辑、复制、启用开关、删除 |
| 校验标记 | 配置有问题的任务会标红，鼠标悬停显示具体问题 |

顶部的统计条会汇总「共 N 个 / 启用 N / 每日 N / 有问题 N」。

### 任务编辑

- **基础信息**：id、名称、描述、图标、分类、类型、刷新费用、启用开关
- **前置任务**：从下拉里挑任意多个任务作为前置（见下）
- **目标**：添加/删除/排序，字段按所选类型自动生成
- **奖励**：同上，不可用的奖励类型会被禁用并显示原因
- **未保存提示**：有改动未保存时，离开页面会提醒

目标与奖励的**顺序有意义**：管理员命令 `/ptxa setobjective` 里的「目标序号」
就是这里的排列顺序（从 `0` 开始）。界面卡片上显示的 `#N` 是**从 1 开始**的展示编号。

### 前置任务（任务链）

在任务编辑页的「前置任务」里选任务即可，可以选择多个：

- 玩家**领取**过全部前置任务的奖励后，本任务才会进入每日抽取池、才可领奖；
  多个前置之间是「且」的关系，「已完成但没领奖」不算数；
- 下拉里**会成环的候选被禁选**（例如 A 已经以 B 为前置时，就不能再让 B 以 A 为前置），
  前端只是提前拦一道，权威判定仍在后端；
- 保存后右侧的「校验问题」会列出前置相关的错误：不存在的 id、自己、成环、前置已被禁用。
  这几类问题都会让**目标任务永远解锁不了**，玩家侧只表现为「这个任务一直不出现」，
  所以务必修掉；
- 任务列表页的「前置」列显示数量，鼠标悬停可看具体 id；搜索框也支持按前置 id 搜
  （想找「谁依赖了这个任务」时很方便）。

### 图标与材质选择

图标、材质、实体这类字段不再需要手打枚举名，点击后弹出选择器：

- 搜索框**同时匹配中文名、英文名和枚举名**——输入 `钻石`、`diamond`、
  `DIAMOND_ORE` 都能找到钻石矿石
- 按「方块 / 物品 / 食物」分类浏览，实体单独一栏
- 列表只包含**当前服务端版本支持**的物品（能作为物品存在的那些），
  因此不会选到本版本没有的东西
- 材质字段支持**多选**（逗号分隔），例如同时把两种钻石矿算作一个目标；
  仍然可以直接手打，逗号分隔的原始写法对熟悉 Bukkit 的管理员更直接
- 留空的字段表示「任意」，选择器不会强制你填

英文名直接来自服务端自带的语言文件，**与当前版本严格对齐**。

中文名需要额外获取，因为 Minecraft 服务端**不自带中文语言文件**（只有英文）。
插件会优先读 `plugins/playerTaskX/editor/zh_cn.json`；文件不存在时会在后台从官方资源下载
一份并缓存到该路径，之后不再重复下载。

- 只要成功取到一次，之后即使服务器访问不了外网也一直有中文名
- 完全离线的服务器可以手动把 `zh_cn.json` 放到上述路径，效果相同
- 若下载被关闭或失败，列表会显示英文名，**用英文名或枚举名照样搜得到**，
  界面上也会明确提示当前只有英文名

> 位置在 `editor/` 而不是 `lang/`：`lang/` 里是**插件自己的语言文件**（`zh_CN.yml`），
> 这份 `zh_cn.json` 是 **Minecraft 的译名数据**，只给编辑器图标列表用。

> 关闭下载：把 `config.yml` 里的 `editor.fetch-chinese-names` 设为 `false`。
> 有些服务器不允许插件访问外网，这种环境建议关闭并手动放置语言文件。

### 目标与奖励的预设

反复填写「挖 64 个石头」这类相同配置很费事。预设把这些配置存下来，建任务时
点一下就能套用：

- 在任务编辑器里点「添加目标 / 添加奖励」时，可以直接选一个预设套用，
  也可以从空白开始
- 反向也支持：把当前正在编辑的目标/奖励**另存为预设**
- 「预设」页面可以新建、修改、删除预设

预设存在数据库的 `preset` 表里（与任务定义、玩家数据同一个库，见 [配置](configuration#存储)），
编辑器里可以新建、修改、删除。插件首次启动会写入一批默认预设作为示例。

> 预设只是编辑器的便利设施：**引擎不认识预设**，它只认任务里实际写着的目标
> 与奖励。因此删掉预设不会影响任何已建好的任务。

### 玩家进度

排查「某玩家为什么没有进度」的入口：

- 左侧列出所有有任务数据的玩家，可搜索，在线玩家有标记
- 选中后右侧显示该玩家的任务记录：任务名、类型、状态、进度百分比、过期时间
- 展开可见**逐个目标的「当前 / 需求」**，一眼看出卡在哪一步
- 点击某位玩家会把该玩家写进地址栏（`#/players/<uuid>`）：这个地址可以直接分享、收藏，
  刷新或直接打开都停在同一位玩家（没带 uuid 时默认选中第一位）

该页面为**只读**，修改玩家数据请用 `/ptxa` 命令。

### 语言文件

左侧选择语言，右侧直接编辑该语言的 YAML 文本。
保存时会先校验 YAML 合法性，格式错误会被拒绝并提示，因此不会因为一次手滑让玩家看到
「Missing message」。

### 导入 / 导出

- **导出**：下载 `quests.json`，包含全部任务定义，可用于备份或迁移到别的服务器
- **导入**：选择 json 文件，并选择导入方式
  - **合并**：保留现有任务，同 id 会被覆盖
  - **替换**：先清空全部任务再导入（相当于用备份还原）

导入结果会显示成功数量与被跳过的条目。

## 表单为什么是自动生成的

任务目标与奖励的参数由**类型自身的 schema** 描述：

```java
public interface ObjectiveType {
    String id();
    String displayName();
    List<ConfigField> schema();     // ← 表单据此渲染
    int match(ProgressContext context, Map<String, Object> properties);
}
```

因此编辑器（以及游戏内 GUI）**不需要为每种类型写界面代码**：
新增一种目标或奖励类型时，只要实现接口并注册，编辑器里立刻就能编辑它。

这也是编辑器里看不到任何「专门为某个类型写死的输入框」的原因。

`ConfigField` 的类型决定了渲染成什么控件：

| 类型 | 控件 |
|---|---|
| `STRING` | 单行文本 |
| `INTEGER` / `DECIMAL` | 数字输入 |
| `BOOLEAN` | 开关 |
| `MATERIAL` | 材质选择器（支持逗号分隔多选） |
| `ENTITY` | 实体选择器 |
| `TARGET` | 方块或实体选择器（两者都可选） |
| `ENUM` | 下拉，候选项来自 `options` |

> 写新类型时请**如实声明字段类型**：把「材质名」声明成 `STRING` 不会报错，
> 但编辑器只好给你一个纯文本框，管理员就得去查 Bukkit 枚举名——
> 这类字段应当用 `MATERIAL` / `ENTITY` / `TARGET`。

## 任务改动何时生效

编辑器保存会**立即生效**：写库的同时更新内存里的任务定义并重建玩家进度索引，
不需要重载，也不需要重启服务器。

概览页的「重载任务」按钮（等同 `/ptxa reload`）用于**从数据库重新读一遍**——
在插件外直接改过库、或换了存储后端之后才用得上。

> 玩家进度与任务定义按**目标下标**关联。插件会记录接手任务时的目标结构指纹，
> 大幅调整目标顺序（或增删目标）后，该任务上已有玩家的进度会被**重置为 0 并在日志里告警**，
> 而不是静默错配到别的目标上。建议在任务尚未发放给玩家时调整顺序，
> 或让玩家刷新每日任务（`/ptx refresh`）重新抽取。
